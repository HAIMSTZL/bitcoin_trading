# 现货网格自动交易系统 · 技术方案

> 适用对象：项目所有者（复盘、调参、后续迭代）
> 版本：v1.0（对应 commit `01cfdbd`）
> 代码位置：`trading/` 包 + `run.py`

---

## 1. 一句话理解这个系统

把一笔钱换成"一排渔夫"：在价格区间的不同高度布好渔网，
**价格跌下来就买一斗，涨上去就卖一斗**，每完成一次"低买高卖"，
差价（USDT）就落袋。系统自动撒网、收网、补网，7×24 小时不停。

## 2. 设计目标与约束

| 项目 | 决策 |
|------|------|
| 交易市场 | Gate 现货，**仅** `BTC_USDT`、`DOGE_USDT`、`ETH_USDT`（代码级硬白名单） |
| 盈利口径 | USDT |
| 策略 | 现货网格（低买高卖赚差价） |
| 运行模式 | 模拟盘先行（真实行情 + 虚拟撮合），可随时切实盘 |
| 可视化 | Web 面板实时查看，开始/暂停/停止手动控制 |
| 安全 | API 密钥只走环境变量；模拟盘不发生任何真实交易 |

## 3. 网格策略原理（通俗版）

### 3.1 核心思想

价格波动是常态。网格策略不预测涨跌，而是把价格区间切成一格一格，
**在每个格子底部挂买单、顶部挂卖单**，价格来回波动一次就收割一次差价。

### 3.2 用真实数据举例

以你的 DOGE 网格为例（2026-08-03 实际启动参数）：

- 启动时 DOGE 价格：`0.0704` USDT
- 网格区间：`0.061952 ~ 0.078848`（±12%）
- 档位数：21 档，每档间隔 `0.0008448`
- 初始库存：3323.57 DOGE（镜像真实账户）+ 0.04 USDT

启动那一刻，系统做了两件事：

```
价格上方（0.0704 ~ 0.078848）：挂 11 个卖单，每单 302.14 个 DOGE
价格下方（0.061952 ~ 0.0704）：挂 10 个买单，每单 0.004 USDT
```

之后的运转规则只有两条：

1. **买单在第 i 档成交** → 立刻在**第 i+1 档**挂出同数量的卖单；
2. **卖单在第 i 档成交** → 立刻在**第 i-1 档**挂回同数量的买单。

于是价格每完成一次"下穿越→上穿越"，就有一对买卖成交，
利润 = 数量 ×（卖出价 - 买入价），以 USDT 计入"已实现利润"。

### 3.3 三种行情下的表现（必须理解）

| 行情 | 结果 |
|------|------|
| 区间震荡（最舒服） | 反复低买高卖，利润持续累积 ✅ |
| 单边上涨 | 库存一路卖光，之后无货可卖。赚了差价但"卖飞"了，少赚了上涨段 |
| 单边下跌 | 一路买入直到 USDT 用完，之后躺平。账面浮亏，等价格回来才能解套 |

**结论：网格是震荡市策略，不抗单边。** 区间参数决定了你的"活动范围"。

## 4. 系统架构

```
┌─────────────────────────────────────────────────────┐
│  run.py（入口）                                       │

│  │    Gate 拉取 3 个币对最新价 → GridBot 逐个撮合       │
│  │    → 成交记录/事件/网格状态写入 SQLite               │
│  ├── PaperAccount（模拟盘虚拟账户，按币对隔离）          │
│  └── LiveExecutor（实盘执行器，默认关闭，双重确认开启）    │
├─────────────────────────────────────────────────────┤
│  Web（FastAPI）                                       │
│  ├── GET  /            面板页面                        │

```

**数据流**：Gate 真实行情 → 网格撮合 → SQLite（trades / events / bot_state / equity_snapshots）→ WebSocket → 浏览器。

## 5. 参数详解（`trading/config.py`）

### 5.1 交易范围

```python
PAIRS = ("BTC_USDT", "DOGE_USDT", "ETH_USDT")
```

硬白名单。实盘执行器对任何白名单外的币对直接拒绝执行，不可通过配置绕过——这是防止"手滑交易其他币种"的最后防线。

### 5.2 网格参数（每个币对独立）

```python
GRID_CONFIG = {
    "DOGE_USDT": {"range_pct": 0.04, "grids": 21, ...},
    ...
}
```

#### `range_pct`：区间幅度（最重要）

以**启动时刻价格**为中轴，上下各浮动的比例。`0.04` = 上下各 4%。

- 调大：覆盖更大行情，单边时不容易"跑出区间"，但每档间隔变大、成交变少；
- 调小：成交频繁、蚕食小波动，价格跑出区间由自动重建机制兜底（见 5.5）；
- 参考（v1.1 起默认）：DOGE ±4%、ETH ±3.5%、BTC ±3%——间距 0.3~0.4%，
  日常波动一天可穿越多次；旧默认 ±12%（间距 1.2%）实测一晚上仅 1 笔成交，已废弃；
- **网格间距必须显著大于双边手续费（约 0.2%）才有净利润**。

#### `grids`：档位数

价格区间切多少格。21 档 = 20 个间隔。

- 档数多 → 每格利润薄、成交频繁，适合小波动高频收割；
- 档数少 → 每格利润厚、成交稀疏；
- 每档订单金额 = 预算 ÷ 档数，档数越多每单越小，**注意实盘最小下单额（约 1 USDT）**。

#### `quote_budget` / `base_budget`：预算（仅 `PAPER_MIRROR_REAL=false` 时生效）

- 总预算 `TOTAL_QUOTE_BUDGET`（默认 233 USDT）按**近期波动率动态分配**到各币对：
  用 `INDICATOR_KLINE` 周期 K 线计算 ATR%（14 周期平均真实波幅），波动越大分得越多——
  网格赚的就是波动的钱；`ALLOC_MIN_W`/`ALLOC_MAX_W`（默认 15%/60%）限制单币对占比，
  计算失败时回退均分。设 `DYNAMIC_ALLOCATION=false` 退回三币对均分；
- 分配结果记入运行日志（含各币对 ATR 与权重）；
- `base_budget`：该交易对初始基础币数量（当前全为 0，纯 USDT 起步）；
- 运行中各币对预算**隔离管理**；自动重建网格时沿用该币对当前余额，不跨币对再平衡。

### 5.3 指标信号过滤（v1.3 防抖版）

每 `INDICATOR_INTERVAL` 秒（默认 120s）对每个币对计算：

| 指标 | 数据源 | 参数 |
|------|--------|------|
| MACD | 15 分钟 K 线（`INDICATOR_KLINE`）本地计算 | (12, 26, 9) |
| KDJ | 同上 | (9, 3, 3) |
| 买卖盘量比 | 盘口前 10 档买单量 ÷ 卖单量 | 阈值 `DEPTH_RATIO_THRESHOLD`（默认 1.5/0.67） |
| 主动买卖量比 | 最近 60 笔逐笔成交，主动买量 ÷ 主动卖量 | 阈值 `TRADE_RATIO_THRESHOLD`（默认 1.5/0.67） |

四项打分汇总为**原始信号**，再经**迟滞确认**（v1.3 新增，治理信号抖动）：

- 连续 `SIGNAL_CONFIRM_COUNT`（默认 2）次同向才允许翻转；
- 两次翻转间隔不小于 `SIGNAL_COOLDOWN`（默认 180s）；
- 抖动期间维持原信号。

确认后的信号驱动网格：**偏空暂停挂买单（不接飞刀），偏多暂停挂卖单（不卖飞）**，
中性双向正常。每次刷新都会检查并补挂耗尽的一侧（防"熄火"）。
设 `USE_SIGNAL_FILTER=false` 可整体关闭。

### 5.3b 趋势市识别与应对（v1.3 新增）

在确认信号基础上叠加 **3 小时涨跌幅**（近 12 根 15m K 线）判断行情状态：

| 状态 | 触发条件 | 系统行为 |
|------|---------|---------|
| 震荡市 ranging | 默认 | 网格正常运行 |
| 趋势上涨 trend_up | 确认偏多 且 3h 涨幅 ≥ `TREND_MOVE_PCT`（默认 4%） | 冻结卖单，握住筹码 |
| 趋势下跌 trend_down | 确认偏空 且 3h 跌幅 ≤ -4% | 冻结买单，握 USDT 等待 |

状态切换记录 `regime_change` 事件，面板网格扫描器有对应徽章。
**语义说明**：冻结 = **停止补挂新单**，不撤销已挂出的逆向订单（保留网格位置）；
`regime` 本身是展示与日志状态，执行层动作由确认信号驱动。
**诚实边界**：趋势市只能"关逆势一侧 + 加宽区间 + 等待"，无法在单边暴跌中盈利。

**冻结后的恢复语义**（重要，边界已明确）：

- `regime` 在每次指标刷新（默认 120s）时**重新计算**，不是单向开关——
  3h 涨跌幅回落到阈值以内、或确认信号转中性，状态自动回到"震荡市"，冻结即解除；
- 解除后若该侧挂单已耗尽，每次刷新都会执行的"耗尽补挂"检查会自动补回挂单；
- 冻结与恢复都有 `regime_change` 事件留痕；
- 已知惯性：3h 滚动窗口回落需要时间，解冻会比趋势实际结束晚 1~2 小时，属预期行为。

### 5.3c 自适应网格区间（v1.3 新增）

`ADAPTIVE_RANGE=true`（默认）时，网格区间不再固定，而是随波动率伸缩：

```
range_pct = clamp(ADAPTIVE_RANGE_MULT × ATR%, RANGE_PCT_MIN, RANGE_PCT_MAX)
            默认 = clamp(10 × ATR%, 2%, 15%)
```

波动大 → 自动加宽（每格利润厚、间距始终大于手续费）；波动小 → 收窄提高频率。
建仓/重建/再平衡时按最新 ATR 计算；再平衡时若目标区间与当前区间偏离超过 50%，
按新区间重建网格（保留利润累计），记录 `grid_recenter` 事件。

### 5.3d 模拟盘手续费（v1.3 新增）

`PAPER_FEE_RATE`（默认 0.001 = 单边 0.1%）：买入按成交金额扣费（得币变少）、
卖出扣费（得 U 变少），已实现利润为**扣费后净利**，面板显示"累计手续费"。

### 5.3e 不亏卖与限时止损（v2.2 新增）

- **不亏卖**：卖单只挂在高于持仓平均成本（avg_cost，含买费）的档位；
  低于成本的库存拿着等回本，重建网格不改写成本基准；
- **限时止损**：水下持仓（现价 < 平均成本）持续 `STUCK_STOPLOSS_HOURS`
  （默认 4 小时）仍无高于成本的成交 → **按现价市价清仓，亏损落账**，
  记 `stoploss` 成交（日志标注"水下超时止损"）；
- 止损后 `STOPLOSS_COOLDOWN_MIN`（默认 60）分钟内该币对不接新买单；
  止损后槽位空仓 → 自动衔接补位筛选；
- `STUCK_STOPLOSS_HOURS=0` 关闭止损（回到纯"不亏卖"死等模式）。

### 5.3f 熔断机制（v1.4 新增，tick 级快速断路器）

信号/趋势通道是分钟级的，闪崩时反应不及。熔断走 **tick 级价格通道**（复用每 3 秒
的行情，零额外开销），内存维护滚动价格窗：

| 层级 | 触发条件 | 行为 |
|------|---------|------|
| 单币对熔断 | 现价相对 `CB_WINDOW_MIN`（默认 15）分钟窗口最高点回撤 ≥ `CB_DROP_PCT`（默认 3%） | 冻结该币对双侧撮合，其余币对正常 |
| 大盘熔断 | BTC 同窗口回撤 ≥ `CB_GLOBAL_BTC_PCT`（默认 4%） | **全系统停止撮合**（行情与熔断检测继续） |
| 恢复 | 不再创新低持续 `CB_RESUME_STABLE_MIN`（默认 30）分钟 | `CB_AUTO_RESUME=true` 时自动恢复并记事件 |

- BTC 只走大盘阈值（3.9% 的正常波动不会拖垮全系统）；
- 熔断触发/恢复均记录 `circuit_breaker`/`circuit_resume` 事件（大盘熔断为 ERROR 级），
  面板状态栏显示红色熔断横幅、币对显示 ⛔ 徽章；
- 熔断期间：不撮合、不补单、不再平衡；挂单保留不动，恢复后继续；
- `CB_ENABLED=false` 可整体关闭。

### 5.5 模拟盘仓位的两种来源

1. **镜像真实账户**（默认）：启动时读取真实现货账户，各基础币按实际可用余额、
   USDT 按持仓价值比例分配。你的账户 = 3323 DOGE + 0.04 USDT，所以只有 DOGE
   网格真正在运转，BTC/ETH 网格空仓待命——忠实反映现实。
2. **存档恢复**：只要 `trading/data/trading.db` 里有上次的存档，就**不再镜像**，
   原样恢复继续跑（状态每 3 秒自动落盘）。想重置模拟盘：删库重启。

### 5.6 网格自动重建（v1.1 新增）

- **价格跑出区间**：`AUTO_RECENTER=true` 时，价格涨破/跌破网格边界即按现价
  为中心重建网格，**保留持仓余额与已实现利润累计**，记录 `grid_recenter` 事件；
- **配置变更**：`range_pct`/`grids` 修改后重启，检测到存档参数签名不一致时，
  按新参数重建网格（保留存档余额与利润），无需手动删库。

### 5.8 槽位制币种轮换（v2.0 新增，`feature/coin-rotation` 分支）

固定 3 个交易槽位（初始 BTC/DOGE/ETH），**事件驱动换币**：

1. **清仓收尾**：卖出后剩余持仓价值 < `SWEEP_DUST_USDT`（默认 5U）且无卖单时，
   最后一笔直接全卖扫尾，让仓位能真正归 0（而不是永远留一点粉尘）；
2. **补位触发**：槽位曾持仓且绝对空仓（base=0、无卖单）→ 触发全市场筛选；
3. **两阶段筛选**（`trading/screener.py`）：
   - 粗筛（1 次全市场 ticker）：24h 成交额 ≥ 5M、振幅 ≤ 15%、单日涨跌 ≤ 20%、
     排除锚定型资产（`SCREEN_EXCLUDE`：稳定币/金银代币）→ Top 20；
   - 精筛打分（0~100）：深度 30 + 点差 25 + ATR 甜区 25 + 热度稳定性 20，
     ≥ `SCREEN_MIN_SCORE`（默认 60）才合格；
4. **补位**：最优候选继承该槽位全部 USDT 子弹建仓，旧币对退役，
   记 `slot_replace` 事件（含候选得分明细）；
5. **宁缺毋滥**：无合格候选则维持原币对，每 `SCREEN_INTERVAL`（默认 1 小时）重筛；
6. 换币后熔断/信号/趋势/再平衡全部自动覆盖新币对；实盘模式下**不自动换币**
   （需人工确认），筛选替换仅在模拟盘自动执行。

### 5.7 定期再平衡：子弹仓位调整（v1.2 新增，仅模拟盘）

每隔 `REBALANCE_INTERVAL` 秒（默认 600 = 10 分钟）执行一次检查：

1. 按当时各币对 **ATR% × (1 + 0.25×趋势信号)** 重算目标权重——波动大、
   信号偏多的币对分得更多子弹；
2. 把三个币对的 **USDT 总额**按新权重重新分配（总额守恒），并用新预算
   **重建买单侧**；持仓和卖单（含成本基准）一律不动；
3. 若最大偏离不足阈值（池子的 `REBALANCE_MIN_DRIFT`=10% 或 1 USDT），
   则本轮不动作——所以实际是"每 10 分钟检查，偏离够了才调"，多数周期是静默的。

每次执行/检查都写入日志（`rebalance` 事件含权重与调动明细）。
为什么不挪持仓：强制变现会把浮动亏损落成实亏并拆散网格，代价远大于收益；
而买单侧在模拟盘是虚拟挂单，重切子弹零成本。

## 6. 撮合规则（模拟盘 vs 实盘）

> **策略定性**：当前配置（全 USDT 起步、`base_budget=0`）本质是
> **多头回撤买入网格（long-only pullback grid）**——上涨时没有库存可卖、
> 下跌时逐层建立多头库存，不是中性网格。评价它应对标"持有 BTC"基准与
> 最大回撤，而非把它当成双向中性策略。

### 6.1 模拟盘

- 挂单静置于固定价位；每 tick 用 Gate ticker 的**最近可用缓存报价**判断：
  价格 ≤ 买单价 → 买成交；价格 ≥ 卖单价 → 卖成交；
- ticker 在独立 worker 中异步刷新以避免网络阻塞策略循环，因此某次撮合通常使用
  最近一到两个轮询周期内（约 3–6 秒）取得的报价，而不是交易所逐笔成交流中的瞬时价格；
  这是模拟盘的明确口径，复盘时应以事件中的报价为准；
- 假设全额成交、无滑点；**手续费按 `PAPER_FEE_RATE`（默认 0.1% 单边）扣除**，
  已实现利润为扣费后净利，并与持仓移动平均成本（avg_cost）账实一致；
- 轮询粒度 3 秒，瞬间触及又拉回的价格可能漏接。

### 6.2 实盘（live）

- 同一套网格信号，成交时改为向 Gate 下**真实市价单**；
- 强制约束：白名单校验 → 单笔 ≤ `MAX_ORDER_QUOTE` → 按交易所规则取整、
  低于最小下单额跳过；
- 与模拟盘的收益差距 ≈ 手续费（单边约 0.1%）+ 滑点 + 漏接误差。
- **注意：实盘执行路径未经过真实下单验证**，启用前务必先用极小预算人工验证一笔。

## 7. 运行控制与状态机

```
        点暂停            点开始
运行中 ────────→ 已暂停 ────────→ 运行中
  │                                  ↑
  │ 点停止（状态落盘+线程终止）        │ 点开始（重建线程）
  └──────────────→ 已停止 ───────────┘

进程重启：从 bot_state 表恢复网格状态 → 待命（已暂停）→ 点"开始"运行
```

- 服务启动后**默认待命**，必须手动点"开始"才交易；
- 三种恢复路径（暂停→开始 / 停止→开始 / 重启进程→开始）结果一致，状态连续。

## 8. 日志与复盘体系

### 8.1 SQLite（`trading/data/trading.db`）

| 表 | 内容 |
|----|------|
| `trades` | 每笔成交：时间、币对、方向、价、量、金额、利润 |
| `events` | 全量事件：挂单、成交、网格初始化、控制操作、异常（含堆栈） |
| `equity_snapshots` | 权益曲线快照（每 10 个 tick 一条） |
| `bot_state` | 每个币对的网格完整状态（断点续跑用） |

### 8.2 文本日志

`trading/data/trading.log`（5MB × 3 轮转），与控制台同步，异常带完整堆栈。

### 8.3 复盘口径

- **已实现利润**：完整"低买→高卖"回合产生的 USDT，衡量网格真实赚钱能力；
- **总权益** = USDT + 持仓 × 现价：随行情跳动，衡量"策略+持仓"整体；
- 两者要分开看：持币本身涨跌会淹没网格利润，别用总权益评价策略好坏。

## 9. 风控设计

1. **币对硬白名单**：代码层拒绝任何非 BTC/DOGE/ETH_USDT 交易；
2. **模拟盘先行**：默认模式不发生任何真实交易；
3. **实盘双重确认**：`TRADING_MODE=live` + `LIVE_TRADING_CONFIRM` 缺一不可；
4. **单笔限额**：实盘单票不超过 `MAX_ORDER_QUOTE`（默认 50 USDT）；
5. **密钥零硬编码**：只从环境变量读取，全库无明文；
6. **异常自恢复**：所有网络/接口异常捕获记录，引擎不中断，下个 tick 自动重试；
   GET 请求网络层失败时**立即换连接重试一次**（POST 下单类不重试，防重复提交）；
   持续中断超过 `API_OUTAGE_ALERT_SEC`（默认 30s）升级为 ERROR 事件 + 面板红色横幅，
   恢复时记 `api_recovered` 事件；
7. **面板仅监听本地回环**（127.0.0.1），不对外暴露。
